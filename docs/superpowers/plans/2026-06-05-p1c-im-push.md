**Goal:** Deliver the IM-push layer (`IMChannel` + `HermesWeixin` primary / `WecomWebhook` fallback / `StubSink` tests) and the orchestrator glue that closes the P1 vertical — the conjunctive grounded-floor gate, a status-message-with-`trace_id` on shortfall, and the end-to-end `run_pipeline` that gates → assembles → labels → pushes.

Live WeChat send (QR token) is owner-performed and out of automated scope; all tests run on `StubSink` + fixtures.

**Tech Stack:** Python 3.11+, httpx (already a dep), pydantic-settings (already used), pytest + pytest-asyncio. No new package dependencies.

## Design fork resolved: thin iLink send client (NOT the hermes-agent library)

**Decision: thin httpx send client.** The iLink send is a single HTTP POST authenticated by a static bearer token (`WEIXIN_TOKEN`) + account id (`WEIXIN_ACCOUNT_ID`), both minted once via the owner's QR login; there is no per-send handshake. `httpx` (already a dependency) covers it in ~15 lines. Importing `hermes-agent` as a library would pull an unreviewed framework in for one POST — a Karpathy-② violation.

**Risk / resolve-during-implementation:** the exact endpoint URL and field names (`account_id` vs `target_id`, `content` vs `text`, header vs body token) can't be confirmed without a live token. Task 3 marks the `_post` body "confirm field names before finalizing"; the unit tests mock `httpx.post` so they are independent of the exact field names. **Fallback trigger:** only if inspection shows the send needs session refresh / multi-step auth that a thin client can't do cleanly in <30 lines — then import `hermes-agent[messaging]` and record an ADR against D-17. Not expected.

```python
The caller reserves BODY_BUDGET when rendering (render_brief max_chars), so
apply_label only prepends. It NEVER truncates — truncation lives in render.py
(orphan-marker-safe). A body over budget is a caller bug → raise (fail closed).

from __future__ import annotations

DEV_PREFIX = "【DEV / UNVERIFIED — 非正式报告】"
MAX_TOTAL = 500
BODY_BUDGET = MAX_TOTAL - len(DEV_PREFIX)


def apply_label(body: str) -> str:
    labeled = DEV_PREFIX + body
    if len(labeled) > MAX_TOTAL:
        raise ValueError(
            f"labeled message length {len(labeled)} exceeds {MAX_TOTAL}; "
            f"render with max_chars=BODY_BUDGET ({BODY_BUDGET}) before labeling"
        )
    return labeled
```

```python
"""WecomWebhook: WeCom group-bot webhook fallback channel.
Docs: https://developer.work.weixin.qq.com/document/path/91770
"""
from __future__ import annotations

import httpx

from marketwind.gateway.im.base import SendResult


class WecomWebhook:
    def __init__(self, *, webhook_url: str) -> None:
        self.webhook_url = webhook_url

    def send(self, text: str) -> SendResult:
        try:
            resp = httpx.post(
                self.webhook_url,
                json={"msgtype": "text", "text": {"content": text}},
                timeout=10.0,
            )
            resp.raise_for_status()
            return SendResult(ok=True)
        except httpx.HTTPStatusError as e:
            return SendResult(ok=False, error=f"HTTP {e.response.status_code}")
        except httpx.TransportError as e:
            return SendResult(ok=False, error=str(e))
```

```python
async def run_pipeline(*, sources: list[Source],
                       make_body: Callable[[], Awaitable[str]],
                       primary: IMChannel, fallback: IMChannel,
                       dev_channel: IMChannel, trace_id: str) -> None:
    """Grounded-floor gate (reuse evaluate_floor) -> assemble -> label -> push.

    Sub-floor: emit status with trace_id to dev_channel and return WITHOUT
    assembling a brief (spec §8). make_body is lazy so a shortfall costs no
    Writer/DeepSeek call.

    floor = evaluate_floor(sources)
    if not floor.passed:
        dev_channel.send(_status_message(floor, trace_id))
        return
    body = await make_body()
    labeled = apply_label(body)
    send_with_fallback(labeled, primary=primary, fallback=fallback, trace_id=trace_id)
```

```python
"""Config-driven IM channel selection (D-17: channels are pluggable)."""
from __future__ import annotations

from marketwind.gateway.im.base import IMChannel
from marketwind.gateway.im.hermes_weixin import HermesWeixin

from marketwind.gateway.im.wecom_webhook import WecomWebhook


def build_channels(settings) -> tuple[IMChannel, IMChannel]:
    """Return (primary, fallback). Stub by default; hermes->wecom for live."""
    if settings.im_channel == "stub":
        return StubSink(), StubSink()
    if settings.im_channel == "hermes_weixin":
        if not (settings.weixin_account_id and settings.weixin_token):
            raise ValueError("WEIXIN_ACCOUNT_ID and WEIXIN_TOKEN required for hermes_weixin")

                               token=settings.weixin_token)
        fallback = (WecomWebhook(webhook_url=settings.wecom_webhook_url)

        return primary, fallback
    if settings.im_channel == "wecom_webhook":
        if not settings.wecom_webhook_url:
            raise ValueError("WECOM_WEBHOOK_URL required for wecom_webhook")
        return WecomWebhook(webhook_url=settings.wecom_webhook_url), StubSink()
    raise ValueError(f"unknown im_channel: {settings.im_channel}")
```

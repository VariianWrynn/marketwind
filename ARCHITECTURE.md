## 2. ★ Autonomous triggering & long-running operation — the project's defining capability

This is the feature that separates MarketWind from a one-shot prompt, and it is **first-class, not plumbing**. The system wakes itself, runs the pipeline through the gates on a calendar-aware schedule, and publishes or emits a status message — with no human in the loop. Every module must be designed for unattended, repeated, calendar-aware triggering, not just single invocation.

- **APScheduler, three job classes**: `cron` (dual cron, see D-18) / `interval` (keyword polling) / `event` (external signals on Redis Streams).
- **Unified `Trigger` protocol**: new triggers implement the protocol and register; the main flow does not change.
- **Trading-calendar service** (D-22): holiday/weekend runs degrade to a news digest instead of emitting an empty report.
- **Durable run loop + degradation**: see `citation/failure-handling.md`. **Note: substituting cached data for today's must be explicitly labeled with its timestamp — never a silent swap.**

## 5. Known engineering gaps (face these before building)

### Gap 1 ★ Scout primary-fetch (highest priority)

The 5/28 real quote-pool audit found **primary source = 0** — everything was media restatement. Under I3, all quantitative claims would jam at Gate 0 or degrade wholesale to `attributed_single`, turning the report into wall-to-wall "据财联社报道".

These primaries are all publicly fetchable (Shanghai Exchange filings, 巨潮 prospectuses, company announcements). **Scout must add a step**: after obtaining a number from media reporting, trace it back to the original disclosure (巨潮 / exchange / company announcement) and attach that as the primary source. This component is not in the current pipeline diagram; without it the system jams at Gate 0 every day.

### Gap 2 No overseas-site crawling

Resolved (D-28). Scout crawls **domestic sites only** — drop the X / foreign-media direct crawl. Deployment is domestic single-node; the overseas-worker / proxy complexity is removed. **Domestic-media coverage of overseas markets is retained**: overnight-US and Philly-SOX content comes from domestic financial media (财联社 / 新浪), so `time_window` values `overnight_us` / `us_extended` stay valid and the pre-market US section survives.

### Gap 3 Cross-report storage (I11 dependency)

I11 cross-report consistency needs to read prior published claims. **Implement a dedicated database for cross-report storage**: `pipeline_runs` (Postgres) must persist each report's verified-claim set (statement + time_window + rendered text), queryable by report/date. This is the data foundation for the correction mechanism (D-14).

### Gap 4 Model & cost — resolved

Resolved (D-26): **DeepSeek V4 Pro across all roles, tokens unlimited**. The earlier cost concern is dissolved. Note: the former 6-key routing was for rate-limit / API-fault tolerance, not for "the model produced garbage this time" — same prompt, different key, same model, same result. Don't conflate the two.

### Gap 5 Intent routing — single-intent will hit a wall

ConciergeBot will receive mixed multi-intent messages in practice (e.g. "今天中芯那段再展开，顺便寒武纪也加进来明天看看" — three intents, mixed tense in one sentence). **A single-intent classifier will hit a wall.** Required: function calling + an explicit intent schema + **ask back when unsure**.

**Asking back is a first-class behavior, not a last resort.** When the parse is ambiguous, the bot must ask a clarifying question rather than guess — guessing wrong on a side-effectful intent (changing the cron, changing a subscription) is the worst outcome. **Side-effectful commands (change cron / change subscription) must always confirm before executing** (D-17 spirit); letting an LLM change a scheduled job on a guessed parse is an accident generator.
